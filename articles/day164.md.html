As you can see from the documentation, its first parameter is a HDC, which is short for "Handle to a device context". We already talked about device contexts when we were talking about drawing stuff to the screen. Back then, we were getting a device context from the window, but in the asset processor we don't have one to use. It's fine, we can just use CreateCompatibleDC with a NULL argument to get one that uses the screen format. When a device context is created, it comes with a default bitmap which is 1 pixel wide and 1 pixel tall. We don't want that, so we will create a new bitmap to replace that default one. Since this is the asset processor and we don't care about being maximally efficient, let's just create a 1024x1024 bitmap that we will reuse for every glyph. We know that, for Handmade Hero, we're never gonna need glyphs that are bigger than that. We can create the bitmap with CreateCompatibleBitmap and assign it as the current one with SelectObject. ~~~~~~~ C++ #if USE_FONTS_FROM_WINDOWS ~~~~~~~ C++ add HDC DeviceContext = CreateCompatibleDC(NULL); HBITMAP Bitmap = CreateCompatibleBitmap(DeviceContext, 1024, 1024); SelectObject(DeviceContext, Bitmap); ~~~~~~~ C++ #else ~~~~~~~ [Listing 2: test_asset_processor.cpp > LoadGlyphBitmap Create the device context and the bitmap.] Actually, since we don't want to keep creating new device contexts every time we call LoadGlyphBitmap, let's declare it as static and only create it the first time. Note that CreateCompatibleDC returns NULL when it fails.
